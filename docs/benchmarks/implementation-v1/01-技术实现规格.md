# 技术实现规格

版本：2026-10-20 / v1。本文中的新增目录、类和命令是实施要求，尚未存在的入口不得宣称已经可运行。已有源码位置以当前仓库复核为准。

## 1. 总体结构：共享能力，两套执行环境

    产品 UI/API -> 产品 Runtime -> 9 项工具 -> BusinessService -> PostgreSQL
                         |                  |
                    ContextPolicy      批准/版本/事务/回执
                         |
                  预算传输与 Trace
                         |
    官方 Orchestrator -> RetailAgentAdapter -> Agent 决策
             |                                      |
       官方用户模拟器                         返回官方 AssistantMessage
             |                                      |
             +----------- 官方 Retail tools/env ----+
                                  |
                           官方 reward evaluator

产品保持原可信 API 确认；Benchmark 按官方政策和对话处理确认，不伪造产品审批，不把 UI 按钮要求强加给官方用户。产品 PostgreSQL 与官方 Retail 环境不共享业务数据库。

优先抽取三个小接缝：消息投影、预算化模型传输、Trace。不要先制造一个通用万能框架。官方适配代码不得导入 BusinessService 去执行零售工具。

## 3. 官方版本与适配合同

固定：sierra-research/tau2-bench，v1.0.1，fc0055dc4e0a316c3f83133267fbd6faaa770992。

上游锁记录：repository、tag、resolved_commit、许可证摘要、锁文件hash、split清单hash、选用policy/tools/evaluator源码hash、Python版本与安装器版本。必须验证 tag 解析结果，不能只保存字符串。

### 3.1 自定义 Agent

继承固定版本的 HalfDuplexAgent，落实两个方法：

    get_init_state(message_history=None) -> AgentState
    generate_next_message(message, state) -> (AssistantMessage, AgentState)

message 可为 UserMessage、ToolMessage 或 MultiToolMessage。状态保存原始可见消息、上下文证据索引、未决工具调用和计数，不保存 Task、目标终态或评分答案。

一次适配器调用只产生下一条合法 AssistantMessage。若含工具调用，将它交还官方 Orchestrator，由官方环境执行。适配器内部不再次执行相同工具，也不在 ToolNode 中提前改环境。

若使用 LangGraph 包装决策节点，应在生成工具意图后停到外部边界；下一次由官方 ToolMessage 回填。不要强行复用包含本地执行器的 Deep Agents 完整循环。最小可用版可以是薄适配器加纯函数策略，产品仍使用 Deep Agents。

整批工具消息一次归并：以官方 call ID 对应结果，不按列表位置猜测；多个call、部分错误、空文本、合法终止均需契约测试。官方文本协议要求一次输出文本或工具调用，桥接按固定官方转换逻辑处理；任何共同规范化必须两组一致并记录，不能只替优化组修复输出。

### 3.2 基线

直接使用官方 LLMAgent，保留其系统指令模板、工具列表、历史处理和决策步骤。不得选 LLMGTAgent、SoloAgent 或向其提供参考动作。传输层施加共同预算/超时不构成完全复刻排行榜配置，报告明确“官方 LLMAgent + 本实验共同执行限制”。

基线与自定义组同样禁止默认通用文件/shell/子 Agent 工具。产品的九工具限制继续有效；Benchmark 使用固定官方工具集合的名字与schema hash。不能全局放宽产品的 forbidden 参数集合；user_id 等在官方环境是否合法由官方schema决定。

### 3.3 工具和评分唯一执行者

官方工具调用次数、错误和环境变化由 Orchestrator 观察，项目仅记录Trace。所有写工具照原规范执行。

官方评分保留 reward_basis。自有“违规提议、无证据参数、重复操作”等诊断单列，不修改官方 reward；参考动作只是评分侧使用，不是给 Agent 的操作清单。

默认禁用自动 review。评估模式先核对实际选中任务的奖励组件：若全部只依赖不需模型的组件，可用官方 EvaluationType.ALL 省去额外 NL 诊断；若任务的正式奖励确实依赖模型评审，必须另列 judge 模型和预算后才执行，不删掉该项来保持零评审成本。

## 4. 防止隐藏答案进入产品上下文

Agent 可见：官方政策、工具schema、实际用户发来的消息、实际工具返回和自己的历史提议。

只有官方用户模拟器可见：其角色所需的隐藏用户目标/行为说明。其状态与 Agent 完全分开，不能共用 ContextState、checkpoint namespace 或 prompt日志回填器。

只有 runner/evaluator 可见：完整 Task、evaluation_criteria、参考actions、目标环境及评分数据。可信runner可按官方协议读取它们，但开发 Agent 不应查看 Retail Test 正文，模型调用不得携带这些字段。

source_guard采用白名单构建Agent输入，禁止直接将Task/Environment序列化。用人为合成的canary字段做泄漏测试，不向正式任务注入标记。还应验证自定义状态没有通过全局变量或闭包持有环境全量数据。

实现者调试只读train；Test选择仅需ID清单。读取同一大tasks.json时，用受控准备脚本仅输出允许的train内容，Test正文不打印到终端/对话。该流程隔离不应被称为操作系统强隔离。

## 5. 统一模型入口和预算

### 5.1 现状限制

当前 BudgetedBailianModel.bind_tools 固定 ALLOWED；PilotGateway 绑定旧scope和业务服务；BudgetLedger.reserve 固定16/8等计数，ModelCall.conversation_id又指向业务Conversation。不能直接复制一个不计账的 LiteLLM 客户端绕过它们。

新增 ExperimentGateway，复用现有安全传输、硬截止、预留与结算语义。旧批次入口与旧默认限制保持，不把任意JSON配置当作新的真实调用权限。

### 5.2 角色和身份

每个物理请求绑定：experiment_id、batch_id、episode_id、task_id（仅账本标签）、variant、trial、role、exact_model、attempt_id、plan_hash。

role至少区分 agent / user / judge / auxiliary。尚未批准的role在网络前拒绝。相同模型承担两个角色也必须分角色统计，并合计消耗同一精确模型额度。

为每个episode-role创建持久账本会话，放在已有持久账本库的专用namespace中，满足当前Conversation外键；不把官方业务数据写进这些会话。新元数据表保存ExperimentRun、Episode、ActorBudget及与旧ModelCall的映射，采用增量迁移。旧数据不重编号、不重置。

项目级、实验/批次级、模型角色级、episode总量及episode-role上限在同一次预留中校验。事务锁按固定顺序获取，避免并发超额或死锁。旧项目总额度仍有效，若新计划超出须另行批准扩额，不能换batch/provider前缀绕过。

另设按provider + region + exact_model归一化的共享ModelQuota/暂停实体，不把role或batch放进其主键。同一精确模型的全部角色和批次先合计核验已知消费与未结算预留，再进入子预算；provider别名必须解析为同一账户/模型身份，不能换别名获得新额度。当前可用额度确认应有时间与账本水位，避免把已包含在余额内的历史消费再次扣减。

任一角色出现未知usage，除原请求保留预留外，还要设置该精确模型的共享暂停；所有相关新实验入口在网络前检查，换role、新batch或新进程都不能解除。预检同时拒绝沿用仍有未知用量的旧模型状态；不改写旧账本，以增量映射建立阻断。只有有证据的人工对账及明确解除流程才能清除暂停，不按超时自动释放。

持久限制字段包括每角色输出上限、请求次数、Token预留、单请求及episode截止、全批累计和墙钟。进程重启/改role不会获得新额度。

### 5.3 上游传输接缝

优先在独立benchmark子进程中接管固定版官方generate最终调用的completion边界，转换为ExperimentGateway并返回官方所需响应结构；保持官方message/policy/tool转换不变。可用明确的依赖注入或进程内固定符号替换，修改仅作用于该子进程，记录源码位置/hash与桥接测试。不修改产品全局LiteLLM，也不静默patch评分器。

官方 agent、user、NL judge可能在不同模块提前导入generate，要逐入口验证实际物理出网均到同一受控传输。通过spy传输统计调用角色，并在测试里禁用默认网络；发现未识别调用者立即失败。

关闭SDK/HTTP自动重试、自动重定向、fallback模型、LLM响应缓存、远程遥测/外部Trace上传。模型自身后续修正仍可继续，但算新的预算请求。不得依赖官方cost异常时返回0或usage缺失被忽略的统计。

收到完整usage先结算，再判协议/业务质量；未知usage保留预留并停批。提供商cached/reasoning等字段若有则原样单列，避免与total重复相加。官方cost未知时记null，不报0元；人民币费用只有价格和账单依据充分时才报告。

基线桥接离线等价测试：相同可见历史与参数，桥接前后准备的messages/tools/tool_choice和官方响应解析保持等价；不调用模型验证等价。Agent/User的确切参数、保留/不支持字段都进入配置报告，不能让SDK悄悄drop_params改变其中一组。

## 6. ContextPolicy：先做可测量的投影，再优化

### 6.1 纯函数接口

    ContextInput = 可见原始历史 + 官方policy + tool schemas + 有来源的观察索引
    ContextPolicy.build(input, context_limit) -> PreparedContext
    PreparedContext = messages + selection_manifest + estimated_size + policy_id

selection_manifest记录每个保留/投影/删除块的来源、理由、字节量；只是测量，不是provider真实usage。原始checkpoint、HTTP轨迹与审计永不覆写。

实现三个候选：full_history、fixed_window、evidence_projection。正式“full”是开发验证后选中的配置别名，不默认等于最复杂配置。固定窗口须按完整交互块裁剪，而非任意消息条数。

### 6.2 evidence_projection的最小版本

- 官方完整policy和工具schema不裁减，免得把更少规则当作优化。
- 当前用户原文、所有仍影响未决任务的限制/确认/撤回原文优先保留；英语Retail不复用中文数量正则推断批准。
- 模型提议始终标记proposal；工具事实仅来自实际返回，绑定实体、来源call与观察序号。业务Fact与模型Assumption分开。
- 对最近工具结果先保持完整；对较旧结果，仅移除字段级确认无后续用途的重复包装和同实体被更新的旧快照。金额、状态、选项、地址、支付方式、SKU和错误信息等不得为省Token直接丢弃。
- 同一次AIMessage的所有tool_calls及对应ToolMessages作为整体保存/投影；混合读写结果不能拆成孤立消息。未决调用保持pending，不伪造结果。
- 用户历史默认保留；不确定哪些旧语句仍有效时宁可保留原文。先减少冗余工具payload，不强求实现自然语言语义压缩器。
- 已执行结果保留操作对象和实际结果；写入后相关旧读快照失效。任何从缓存/旧上下文推导出的信息不能替代产品提交时的事务重检。
- 超出上下文预算且无法安全压缩，返回明确context_limit状态，不丢policy、不改原始用户意思。

可选动态优先级：完整policy/schema > 当前用户及未决调用 > 当前实体最新结果 > 确认/撤回原文 > 其他历史。优先级仅用于选择，不能把低优先级事实改成另一个值。

测试：跨十轮保留原订单、改口、多个商品、撤回/否定、部分工具失败、多call配对、写后失效、旧实体不串用、上下文限额失败、原始审计hash未变。采用合成场景和train可见轨迹，不读取test答案。

### 6.3 工具结果复用的范围

第一版不在官方Orchestrator中截获写操作，也不伪造官方工具执行成功。产品现有政策检索缓存可保留，但它省的是本地检索，不自动减少模型Token。

公开基准优先优化“已看过的信息不必重新发给模型”；若开发Trace确实显示重复读瓶颈，再研究工具结果复用。必须证明环境无外部变更、工具纯只读、同参数/身份/实体、写后可靠失效，且保持官方轨迹与评分语义；做不到则放弃，不为多一个术语改变环境。

缓存命中应区分模型提议调用数、实际工具执行数、缓存命中数。返回同样长的结果可能不省模型Token，不能预设收益。

## 7. Trace与指标数据合同

追加式事件字段：schema_version、run/episode/variant/trial、role、sequence、monotonic_time、event_type、parent_id、message_id/tool_call_id、payload_ref、content_hash。

事件至少包括model.request_reserved/sent/settled/unknown、context.prepared、tool.proposed/completed/failed、user.message、environment.terminated、evaluation.completed、run.stopped。

逐题结果包含：官方reward及组件、completion_status、termination_reason、Agent/User/Judge输入输出与总Token、物理HTTP数、工具提议/执行/重复读、上下文投影大小、episode墙钟、模型等待时间、unknown_usage、错误标签、raw_trace_ref。

task_id、评分与隐藏目标只属于外部统计元数据，不能进入模型提示词。原始轨迹本地保存，公开报告去掉密钥、账户地址和敏感运行信息。

重复读定义：同一episode中工具名+规范参数+可观察环境变更序号相同的再次读；仅同参数但环境已变不算可消除冗余。参数无效与业务拒绝分开，OUT_OF_STOCK不是schema错误。

## 8. 产品侧最小接入

将通用ContextPolicy挂到现有BusinessBoundary的模型调用前；保留产品身份、数量证据、确认续跑和事务检查。新策略作为显式profile，旧full默认不立即改变。用现有业务回归证据验证兼容。

RAG第一版不扩语料、不升级权重。只核对实际factory的retrieval_profile与会话注入，支持明确配置bm25/hybrid-rerank，Trace记录实际生效配置。官方Retail默认全文policy，因此这轮基准不把产品RAG当成成功率提升来源；RAG对照如后续开展应独立数据与预算。

产品可靠性实验详见03文件。真正发现旧owner仍可推进非法状态后，再考虑引入fencing generation或提交事务中的所有权CAS；不能把预检查租约当成完整隔离保证，也不先做无依据的大规模重构。

## 9. 必须通过的离线契约检查

- 官方单/多工具及错误回传；只有官方环境实际执行一次。
- 普通LLMAgent基线没有GT/Task/答案；角色上下文互不串用。
- Agent/User/未授权Judge全部被网关识别，默认出网路径不可用。
- 未批准、hash变更、超额、usage未知、异常退出后预留保留。
- 重启与并发预留不能重置角色/episode/全局预算。
- 上下文策略只改投影、保持消息配对和官方完整policy。
- 官方reward不被项目诊断覆盖；失败题、not_run和缺usage不被悄悄过滤。
- product scope仍只有原权限；benchmark scope不能开放普通Web真实入口。
