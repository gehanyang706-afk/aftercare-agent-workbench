# 冻结业务契约 v1

日期：2026-10-17。依据 docs/design/01-架构与验收规格.md；机器配置为 configs/business-rules.v1.yaml。
本阶段冻结规则，业务执行将在阶段 1 实现。所有业务均为自定义模拟，不代表任何真实商户政策。

## 产品边界与终态

单服饰鞋类模拟商户，多消费者/订单/商品行/尺码颜色；身份来自服务端演示会话。
本机监听，没有生产认证，不连接真实支付、商家、物流或消息平台。

| 操作 | 资格 | 成功事实 |
|---|---|---|
| 查询 | 仅当前 principal 所属订单 | 只读正确状态 |
| 取消 | PAID_UNSHIPPED，整单，无并发处理中售后 | CANCELLED + 模拟退款请求，不能说到账 |
| 退货 | DELIVERED，交付后不超过 168 小时（含），未使用且可退 | 创建 RETURN_REQUESTED 申请，不能说已退款 |
| 换货 | DELIVERED，交付后不超过 360 小时（含），未使用且可换，同系列等价变体，库存足够 | 创建 EXCHANGE_REQUESTED 申请和库存预留，不能说已寄出 |
| 缺货 | 有用户明确的备选授权才可提出退货 | 新预览；否则澄清/人工，禁止自动改成退货 |
| 争议/超范围 | 不自行认定质量责任 | HANDOFF_PENDING 工单和证据 |

退换每次一个订单的一个商品行及数量；活动申请占用总量不得超过原购买数量。
不同订单可以在同一会话依次办理，不承诺跨订单原子操作。
取消退款请求金额取原支付整数分。普通退货/换货模拟运费报价均为 800 分、消费者承担；
这是对任务书“版本化运费”的明确默认值，展示用，不实际收取或扣减。争议运费转人工。

## 时间、政策和执行

注入时钟、带时区 UTC、以小时差判断边界，界面 Asia/Shanghai。
资格政策随购买订单版本保存；流程政策使用申请时有效版本。任何预览依赖政策版本变化都需重校验。
后续政策语料必须与本契约一致，独立测试不得仅复用生产资格函数当答案。

新普通消息递增 intent_revision 并使旧预览失效；聊天“好的”不是批准。
预览 600 秒失效，绑定 principal/conversation/preview/参数 hash/intent_revision/订单和政策版本。
可信确认 API 只接受预览 ID 和决定；金额、用户身份、approved 均不能由模型指定。

提交在一个 PostgreSQL 事务内按稳定顺序锁住意图、预览、订单行和库存；
查幂等回执，校验授权与当前资格，写申请/库存/订单、回执和审计，然后提交。
同 key 不同请求报冲突；换 key 也不能绕过 preview 的唯一操作关系。
预览不锁库存；提交竞争失败要重新规划。库存预留到明确处理/取消才释放。
响应丢失先查询同 operation，不盲目重写；后来的改口不能伪称撤回已经提交的操作。

框架 checkpoint 负责图执行位置；业务事实和操作唯一性由数据库事务与约束负责。
本阶段没有业务终态实测，不能据此写简历成功率。
