# 分阶段执行指令：交给编程 Agent

本文件提供阶段 0—7 的执行包。总规格见 01，模型与评测约束见 03。所有命令都是要实现的 CLI 契约，设计阶段尚不可运行。

默认解释器为新项目 `.venv/bin/python`；下面简写为 `python`。依赖工具选型由阶段 0 固定，后续不混用多个包管理器。

## 共用交付格式

每阶段写 `docs/handoffs/phase-XX.md`，内容必须包含：

1. 本阶段可用能力及对应业务示例。
2. 精确运行命令、退出码、验证输出所在路径、通过/失败/跳过情况。
3. 从输入到输出的一条完整数据流，最多五个核心代码入口。
4. 关键决定及其理由，发生过的实际故障及修复；没有故障就不编故事。
5. 已实现、已验证、待真实模型验证、未实现四种状态。
6. 用户的一个体验任务与三个理解问题。
7. 下一阶段前置条件；需要用户处理时写出具体原因和最小操作。

工作区为独立项目，不修改既有项目。普通实现与修复做完再交接，不把测试失败交给用户自行排查。可以在阶段内部并行前端/测试/文档，但核心业务契约和同一文件必须保持单一负责人。

**用户理解：** 做一次正常取消、一次重复点击、一次换货，解释为什么模型不负责最终资格和金额计算。
