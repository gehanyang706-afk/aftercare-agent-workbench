# 五分钟演示脚本

工作台：http://127.0.0.1:8128。画面中的“脚本模拟”需明确说明；它展示工程链路，不是现场真实LLM性能。模型真实证据看results-summary.md，不为演示追加真实调用。

1. 30秒：选择小林，进入工作台、新建会话。左侧展示可访问的订单，说明身份由服务端决定，模型不能替用户越权查单。
2. 90秒：在可办理的S1002上输入“S1002 只退其中一件，另一件保留。”观察预览中的订单、数量、模拟费用。先不点击确认，再输入“暂不提交。”观察旧卡失效及“已按要求暂不提交”，无回执。说明暂停是应用事件，本轮不再调用模型。
3. 90秒：新建会话，重新输入同一明确退货诉求。核对当前订单仍可办理，再点击“确认并提交”。只在确实希望消耗演示数据时演示此步；产生唯一operation和最终回执告知，刷新页面仍可查。若现有数据已占用/超期，如实展示拒绝，勿清空真实账本恢复初态。
4. 60秒：打开docs/experiments/complementary-regressions-v1.md，指认历史真实丢响应案例的事务后故障、同operation查询、唯一申请/预留。当前普通镜像未开故障注入，不声称现场触发。
5. 30秒：打开最近数量报告，说明冻结评分3/4而数量过程3/4，且不是同样的三题。08无副作用仍保留先猜2件的错误；07脚本措辞未投递用户选择，不能冒充“等待分支通过”。

讲解主线：模型提出动作→后台查真实数据→预览绑定版本→可信确认→事务提交→回执型告知。图结束不等于业务结束；业务已有回执也不等于模型/评测未停止。

演示恢复：新建会话保留旧记录；停止app/worker后重启保留数据。库存/占用真实地影响后续演示，不能重复消耗同一订单凑成功。不要demo reset、down -v、删batch-state或账本。需要干净初态时使用现有离线测试入口aftercare_test，勿同时运行pytest，勿把测试库用于保存用户演示。
